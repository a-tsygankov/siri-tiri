# Phone export archive and analysis design

Status: approved by the user; implementation on PR #17. Date: 2026-11-26.

## Purpose and scope

Import the existing PWA exportVersion 1 / protocolVersion 1 JSON plus its separately shared WAV files into a durable offline archive. Preserve original recordings and every capture/review/tombstone as evidence. Make native-rate phone audio usable by the existing YAMNet analyze command. Owner context is never converted into audible-meow labels or inferred intent.

The user selected a separate local archive. Direct live-database ingestion would require migrations, job scheduling and tombstone policy; cloud download would require a local sync client. Both are deferred. There is no PWA change, network upload, live service integration, detector activation or embedding classifier in this increment.

## Commands and storage

`manage.py import-bundle BUNDLE --audio-dir DIRECTORY [--archive-root PATH]` accepts .json and .json.txt content. Default archive root is ignored `local-service/imports/`. Source WAV filenames must be single safe basenames; reject absolute paths, traversal, Windows drive/ADS syntax, reserved names, case-insensitive collisions and links escaping the audio directory. Never use identifiers as unchecked paths.

Each complete import is an immutable directory keyed by the original bundle SHA-256. It contains the byte-exact original bundle, verified original WAVs addressed by SHA-256, versioned 16-kHz WAV derivatives, and a JSON manifest. No persistent aggregate SQLite index is needed initially. Repeated identical import verifies an existing complete artifact and returns it; it never silently overwrites edited evidence. New exports create new snapshots. Consequently records-only updates do not silently borrow history or audio from unrelated snapshots. They retain metadata and report missing audio; the owner can import Export all or supply missing files and retry an incomplete attempt without replacing its evidence.

Implementation decisions: incomplete attempt names use a 16-character bundle-hash prefix plus a full UUID to stay within ordinary Windows path limits; the full hash remains in the manifest. Paths that would exceed 259 characters fail before publication with guidance to use a shorter archive root. Expanded generated manifests have a separate 64-MiB bound, checked before publication and during verification; the source JSON limit remains 16 MiB.

Publish a snapshot by staging and atomic directory rename. Validate metadata and all supplied files before publication. Invalid input leaves no published snapshot. Missing manifest-listed files are represented by explicit `missing_audio` rows and yield exit 2. Incomplete imports publish an immutable attempt directory named with bundle hash plus UUID, preserving the original JSON, every verified supplied WAV, any derivatives and a coverage manifest. Retrying with more files can publish a complete hash-keyed snapshot without overwriting prior attempts. Malformed metadata, checksum mismatches and conflicting content under one message ID exit 1 with no publication. Complete import exits 0. Capture/review forks are preserved as incomplete evidence, yield exit 2 and exclude only the affected events from analysis. Bound JSON to 16 MiB, each WAV to 3 MiB, metadata arrays to 10,000 entries each, and total supplied audio to 600 MiB. Build output incrementally without loading the whole dataset into memory.

## Validation and evidence

Reject duplicate JSON object keys, nonfinite numbers, incompatible versions, malformed envelopes and unsupported audio metadata. Validate UUIDs, timestamps, integer bounds and the current owner-review contract with standard-library validators; no new mandatory API dependency. Match manifest clip/event identifiers, hash, size, rate and duration against capture history. Exact duplicate messages are idempotent; same message ID with different canonical content is a conflict. Preserve review revisions/base revisions, deleted reviews and tombstones. Missing predecessors are explicit unresolved history, not invented revisions. Multiple competing capture heads or review revisions are reported as conflicts and block analysis for the affected event; never pick a winner from timestamps.

Validate capture supersession within the same event, reject cycles, and validate trim source identifiers/hash/rate/range/version against the root capture when present. Only manifest-listed WAVs are required for import completeness. Capture history may name superseded trims whose audio was never exported; these do not block completeness. A current live capture without audio or a manifest entry remains records-only and has insufficient analysis coverage, but its metadata can be completely archived. A trimmed export may omit its original WAV; preserve source provenance with an explicit original_audio_not_supplied limitation rather than reconstructing it. That absence does not block completeness or analysis of the verified trimmed WAV. Analysis must state that the original-to-trim sample relationship was not verified. If the original WAV is available, verify its checksum and sample-aligned cut matches the supplied trimmed PCM. Restores resolve to original audio. Tombstoned events retain imported evidence but are excluded from analysis by default. Import is an archival operation; document that it does not implement secure deletion or cloud tombstone propagation.

## Audio pipeline and analysis

Phone input is mono uncompressed PCM16 WAV at 16,000, 44,100 or 48,000 Hz, nonempty and at most 30 seconds. Verify full frame data and header metadata, SHA-256, byte size and duration within 1 ms of recorded rounded milliseconds. Reject unsupported formats/rates and truncated WAVs. Preserve supplied files byte-for-byte.

Use the existing pinned NumPy 2.2.6 / SciPy 1.15.3 environment. A new independently versioned phone preprocessing module uses float64 normalization, scipy.signal.resample_poly with rational factors (160/441 or 1/3), Kaiser 5 window, constant-zero padding, nearest-even PCM16 quantization and clipping counts. At 16 kHz preserve samples without filtering. Record source/derived hashes, sample counts, rates, clipping, pipeline version and dependency versions. Do not change the established CatMeows preprocessing version or the live worker input contract.

Extend `manage.py analyze WAV` to use this versioned native-rate conversion in memory for phone rates while preserving existing 16-kHz mono/stereo behavior. Include source hash/rate and conversion provenance alongside YAMNet scores. Archive-derived WAVs remain compatible with existing 16-kHz analysis. Add `manage.py analyze-import MANIFEST` to analyze only unambiguous current nondeleted captures with verified derivatives; emit a new immutable JSON result report with per-event success/failure, model identity and preprocessing provenance, never mutate reviews or source artifacts. Missing/unresolved/conflicting events have explicit coverage and no fabricated scores. Analysis exit 0 requires every eligible event to succeed, otherwise exit 2 for insufficient coverage or 1 for inference/runtime failure.

## Verification and handoff

Regression tests cover normal and repeat imports, unchanged originals, records-only updates, deleted events/reviews, partial shares and retry, unsafe paths/links, conflicting IDs, invalid hashes/headers/versions, capture/review forks, trim and restore provenance, missing originals, truncated audio, and bounded inputs. Numerical tests verify 44.1/48-kHz output lengths, silence, tone frequency and downsampling alias rejection; preserve existing CatMeows regressions. Generate at least one fixture using the real PWA buildBundle/encodeWav/buildTrim code and run import plus real YAMNet analysis on it, explicitly marked synthetic.

Run Python core and pinned inference suites, PWA Node tests, diff checks and relevant CI. Update root/service/PWA READMEs, CODEX_HANDOFF and PROJECT_PLAN with actual results and commands. New code/docs go through a feature branch and PR; no automatic merge. No real phone or Tiri recording validation is claimed. Removing the new commands restores previous behavior; keep archives intact for rollback. Fine-grained module names and error codes are builder choices.
